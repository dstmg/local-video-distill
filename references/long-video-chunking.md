# 长视频分块读法（>30 分钟 / >1500 行 MT 必读）

一次性把整份逐字稿塞进上下文会**爆上下文、且提炼质量崩**。必须分块打标 + 逐块精读 + 回捞锚点。

## 阈值
- **短**（<30 分钟 / <1500 行）：可直接通读，走 Stage3 即可。
- **长**（≥30 分钟 / ≥1500 行）：走本分块法。

## 四步法

### 1. 先摸骨架（不逐句读）
用 Grep 抽「结构词」定位章节边界：
```bash
# 定位"第一步/核心/注意/误区"等教学信号词的行号，看分布
grep -nE "第一步|第二步|第三步|核心|关键|注意|误区|结论" 原始提取.md | head -80
```
目的：拿到一张「行号 → 主题」的粗地图，不求细节。

### 2. 按块精读（带行号 offset/limit）
按骨架把 MT 切成 5–8 块，每块 ≤400 行，用 Read 的 `offset`/`limit` 逐块读。**每块读完记 3 件事**：
- 这块讲什么（1 句）
- 关键可操作步骤/数值（挂行号→时间戳）
- 坑/误区（挂时间戳）

### 3. 回捞高价值段
对步骤密集、含数字、含"坑"的段，用 Grep 带 `-C` 上下文精读（如 `保本|投产|出价|限额|注意|不要`），确认真实内容再落笔。

### 4. 汇总成结构
把各块的「一句话 + 步骤 + 坑 + 时间戳」汇总，按 teaching-note-spec 组装 Stage3 HTML / Stage4 技能包。

## 铁律
- **每个结论挂时间戳**（`mm:ss` 或行号→mm:ss），不能凭印象写。
- ASR 有错字/口语：**忠于原意、不逐字照搬噪声**；关键数值若疑似识别错，回看该时间点确认，标「以原视频为准」。
- 繁体/方言稿：先判断语种与简繁，必要时提示用户（opencc 可转简）。
- 读不完就**明确报告读了哪几段、跳了哪几段**，不要假装全读了。

## 反例
- ❌ 一次性 Read 整个 2000 行文件然后"总结" → 必丢细节、易编造。
- ❌ 只读开头几百行就下结论说"这课讲了…" → 严重失真。
- ✅ 分块 + 挂锚点 + 明示覆盖范围 → 忠实可回溯。
